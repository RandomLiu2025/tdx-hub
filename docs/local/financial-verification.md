两期均为“净利润 = 归母股东净利润 + 其他权益工具持有者净利润 + 少数股东损益”。
DAT 三项字段只覆盖其中三个项目，不能把 `FINVALUE95 = FINVALUE96 + FINVALUE97` 当作通用硬约束。

| DAT 字段或差额（人民币元） | 20250630 | 20260630 |
| --- | ---: | ---: |
| FINVALUE95（净利润） | 6,807,780,864 | 9,898,971,136 |
| FINVALUE96（归母净利润） | 4,652,047,872 | 7,149,643,776 |
| FINVALUE97（少数股东损益） | 1,842,561,024 | 2,425,725,952 |
| `95 - 96 - 97` | 313,171,968 | 323,601,408 |
| 官方其他权益工具持有者净利润 × 1,000 | 313,172,000 | 323,601,000 |
| 差额与官方第四项之差 | -32 | 408 |

最后一行来自前三项各自的 float32 舍入；不是百万级的源数据错误。核对计算为：

```python
import struct


def stored_yuan(thousand_yuan):
    return struct.unpack('<f', struct.pack('<f', thousand_yuan * 1000))[0]


assert [stored_yuan(x) for x in (9898971, 7149644, 2425726)] == [
    9898971136.0, 7149643776.0, 2425725952.0,
]
```

**处理决定：不改写这两条源记录、不把残差回填 FINVALUE97、不把其他权益工具净利润并入 FINVALUE96。**
三条解析路径的离线回归用例保留这一非零差额，避免将来引入错误的自动修正或拒收规则。

### 原报与追溯调整不能混用

2026 年报告“公司主要会计数据和财务指标的说明”明确：2025 年下半年合并西北矿业等公司的财务报表，
构成同一控制下企业合并，对相关财务数据进行了追溯调整。

2026 年合并利润表中的 **2025H1 比较列**为（人民币千元）：净利润 7,389,014、归母 4,839,084、
其他权益工具持有者 313,173、少数股东 2,236,757。主要会计数据表同时列示的归母调整前数为 4,652,048。
这与 2025 年原报不同，但不能据此认定本次 20250630 DAT 样本有误：该样本三项对齐的是原报。

SDK 的 `report_date` 是报告期，不是公告日；当前结果不携带完整公告版本、重述版本及历史可得时间。
因此不能据此承诺回测时点正确，也不能默认跨期文件已统一到同一重述口径。
